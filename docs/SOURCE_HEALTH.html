MONITORING DIAGNOSTICS

What source health actually means

A source badge describes the latest automated fetch and parser result. It does not promise that a retailer has inventory, and a successful scan does not prove every product was discovered.

StatusMeaningDoes not mean
MATCHESThe page/feed was fetched and the current parser recognized one or more Pokémon entries.It does not mean every product was captured or all items are in stock.
NO MATCHThe page responded, but the parser recognized zero usable Pokémon entries.It does not mean the retailer has no Pokémon products. The page may need a retailer-specific adapter or JavaScript rendering.
ISSUEThe request failed before parsing, for example due to connection timeout, blocking, TLS, DNS, or HTTP error.It does not prove the retailer is offline for human visitors.

What needs work next

  1. Build and maintain retailer-specific adapters instead of assuming all catalog pages use the same HTML layout.
  2. Record HTTP status, final URL, content type, page title, recognized count, and a short diagnostic for each failed scan.
  3. Keep sanitized HTML fixtures and parser tests for each retailer.
  4. Verify title, category, image, price, and stock state independently.
  5. Keep parser misses separate from request failures. Never display a blocked or unrecognized source as a successful match.

Why an item may have no image or price

An image or price is only shown when the retailer exposes one in structured product data, product-card markup, or known metadata. Some sites load this data later with JavaScript, return placeholders, or block external image hotlinks. In those cases the dashboard uses a neutral fallback and does not invent an image or price.

Manual diagnosis

  1. Open the source URL from the dashboard and confirm the Pokémon products are visible in a normal browser.
  2. Open the matching GitHub Actions run and expand Scan sources and send email digest.
  3. For NO MATCH, determine whether the returned page HTML contains product titles, links, images, and price data.
  4. For ISSUE, inspect the complete connection exception or HTTP status.
  5. Save a sanitized response fixture before writing a retailer-specific parser. Remove session, cart, account, address, and other personal data.
