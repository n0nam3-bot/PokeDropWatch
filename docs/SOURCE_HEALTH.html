POKÉDROP WATCH GUIDE

How PokéDrop Watch works

PokéDrop Watch checks configured retailer and Pokémon news pages on a schedule, looks for product listings or articles, compares the results with saved scan history, and publishes changes it can verify. The dashboard reports what the automated request and parser could read. It is not a promise that a retailer has stock or that every product on the retailer's website was found.

How often the monitor checks

The GitHub Actions workflow is configured to start every 15 minutes. This is the intended interval, not a guarantee that GitHub will start every scheduled run exactly on time. ZIP uploads and manual workflow runs also trigger scans. The Last checked timestamp records the latest completed monitor run and identifies whether it was a scheduled check, ZIP upload, or manual run. The scan step is configured to run even when automated tests fail, so a red workflow can still have refreshed the dashboard.

Reading “Last checked”: compare the timestamp with your local time. A timestamp several hours old means the dashboard is showing an older successful scan, not that the stores have been rechecked and confirmed unchanged. Check the latest PokeDrop Watch run in GitHub Actions. A failed “Run automated tests” step prevents “Scan sources and send email digest” from running.

What the source statuses mean

StatusWhat happenedHow to interpret it
MATCHESThe page or feed responded and the parser recognized one or more usable Pokémon entries.At least one listing was read. It does not mean every listing was found or that every item is available to buy.
PARTIALOnly some configured URLs responded or produced usable results.Some coverage is available, but this source was not fully checked. Failed or blocked alternate routes may hide additional listings.
BLOCKEDThe retailer returned an access-protection or bot-check page.The HTTP request may have returned a page successfully, but it did not expose usable inventory. This is not a normal parser miss.
NO MATCHThe request succeeded, but the parser found zero usable Pokémon entries in the returned content.This is a parser miss, not proof the retailer has no Pokémon products. The site may render results with JavaScript, have changed its markup, return different data to automated requests, or require a session/location.
ISSUEThe request failed before usable content could be parsed, for example a connection timeout, retry failure, block, DNS/TLS failure, or HTTP error.This is an automated-access or source-availability problem. It does not prove the retailer's public site is unavailable to people.

Each configured source can contain more than one URL. “2/2 pages responded” means both configured URLs returned content, not that the parser found products on both. One working alternate may still provide results if the primary URL fails.

Example: a summary of “3 source matches · 5 parser misses · 2 request errors” means three source groups contributed parsed Pokémon entries, five groups responded but produced no recognized entries, and two groups could not be fetched. If the catalog says 176 listings, that is the number of products the monitor currently recognizes and tracks—not a count of every product on those stores, and not a guarantee they are in stock.

Source matches

The number of configured source groups whose parser recognized Pokémon entries. It is not the number of pages that responded.

Products tracked

The number of distinct saved product records across retailer catalogs. This includes last-known listings when a source is blocked or its latest request fails.

New alerts

Events currently counted in the latest monitor state, such as a first discovery, observed restock, price drop, or news item.

Configured sources

The number of enabled retailer/category/news source groups. A group may request one URL or several alternatives.

How a scan becomes an alert

  1. Fetch: the scheduled GitHub Actions monitor requests each configured source URL and its alternatives.
  2. Parse: retailer-specific and shared parsers look for product titles, links, images, prices, release dates, and stock indicators.
  3. Normalize: titles and links are standardized so duplicate pages and tracking URLs are less likely to create duplicate listings.
  4. Compare: the current catalog is compared with saved product and stock history to identify meaningful changes.
  5. Publish: the latest status, catalog, and alert events are written to the public dashboard data file.
  6. Notify: eligible events are matched against the categories and retailer/source preferences of verified, Active subscribers.

The monitor can only report information exposed to its automated request. A normal browser can show additional results because it runs page scripts, uses a logged-in session, has location context, or receives a different version of the page.

Product filters

Item type narrows listings to TCG, plush, collectibles, games, accessories and apparel, or news. Retailer narrows products to Amazon, Walmart, Best Buy, Target, Pokémon Center, or GameStop. Exact title requires the search phrase to match the normalized title rather than matching only part of it.

Latest activity shows detected events. All tracked products shows catalog listings even when they do not have a recent alert event. Clicking a product image or its View Item link opens the retailer's product page in a new tab.

How email notifications work

  1. A visitor chooses the product categories and retailer/news sources they want to follow, then requests a verification code.
  2. A six-digit code is sent to the entered mailbox. It expires after 10 minutes and can only be used once.
  3. After successful verification, the application is saved with Pending status.
  4. A Gym Leader reviews the application. Only Active subscribers are eligible to receive matching alert emails.
  5. Subscriber preferences are checked against each event before an email is sent. Unsubscribe requests also require a one-time email code.

Email verification proves control of the mailbox; it does not automatically activate notifications. A Pending application must still be approved by a Gym Leader.

How Gym Leader management works

The Gym Management page is the private review area for email applications. It uses the Apps Script backend for sign-in and subscriber actions. It does not use public browser access to the subscriber database.

Sign-in and Password reset

  • Sign in with the Gym Leader email and password configured for the Apps Script project.
  • Use Forgot password? to request a one-time reset code at the configured Gym Leader mailbox. The code expires after 10 minutes, can only be used once, and the replacement password must be 12–128 characters.
  • Sign-in attempts are rate-limited. A temporary lock is applied after repeated incorrect passwords.

Application states and available actions

StateMeaningGym Leader action

Sessions and security

  • Gym Leader sessions expire after one hour. Sign in again when a session expires.
  • Subscriber records are stored in Firestore and read or updated by the server-side Apps Script backend.
  • Service-account credentials and password secrets remain in server-side configuration. They must not be copied into public website JavaScript.
  • Firestore browser rules are intentionally private. Do not make subscriber records publicly readable or writable to troubleshoot the Gym Management page.

Why a product may have missing details

  • No image: the page may not expose a usable product image, may return a placeholder, or may block external image loading.
  • Price not listed: the source may hide the price until a page script runs, require a location/session, or expose a price format the parser cannot interpret. The monitor does not invent a price.
  • Unknown availability: no reliable in-stock or out-of-stock indicator was found. The dashboard does not guess.
  • Missing release date: the retailer did not publish a date in the structured data or product markup the monitor received.

Source layouts and access behavior can change. A parser miss should be investigated with the corresponding scan log and a sanitized response sample rather than treated as proof that no product exists.
