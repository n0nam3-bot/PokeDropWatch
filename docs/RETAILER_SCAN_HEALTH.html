MONITORING GUIDE

How retailer routes are scanned

PokéDrop Watch keeps each distinct retailer search separate. Pokémon Center TCG and Plush, for example, have independent histories because they can return different listings. The dashboard groups them under one retailer card so the watchlist is easier to read; it does not combine their stock histories.

The monitor currently has 20 category/search routes across 7 retailer and news groups. It selects one route per retailer in each scheduled 15-minute scan. Retailers with three routes cycle through them in roughly 45 minutes; retailers with four routes cycle through them in roughly 60 minutes. A retailer with only one route is checked on each scheduled run.

Why stagger the routes? It avoids requesting every category page from the same retailer at once. A route marked SCHEDULED has not been requested in the current interval; its previous check time and last-known listings remain visible.

Reading the route badges

BadgeMeaningWhat the listing data means
MATCHESThe selected page was read and the parser recognized current product or news entries.These entries were recognized in this scan. It does not guarantee an item is still in stock at checkout.
PARTIALA route was blocked, failed, or required a fallback before entries were found.Any recognized results remain visible, but a route warning is also recorded.
SCHEDULEDThis route was not selected in the current round-robin interval. No request was made.The previous check time and saved records are retained. They are not a current inventory confirmation.
COOLDOWNThe retailer is temporarily paused after an access challenge or repeated request failure.No request was made for this route while the shared retailer pause is active.
NO MATCHThe checked page responded, but the parser found no usable Pokémon product/news entries.This is not proof that the retailer has no Pokémon products or stock.
ISSUEAll attempted endpoints failed at the request layer.Current inventory could not be confirmed. Check the matching GitHub Actions scan log.
BLOCKEDThe response contained a retailer access challenge such as “Robot or human?” or “Pardon Our Interruption.”An HTTP response alone is not considered a usable retailer page. The monitor does not solve CAPTCHAs or bypass access controls.
FALLBACKA true backup endpoint was used because the primary endpoint failed, was blocked, or returned no recognized entries.The route remains PARTIAL even when the backup found entries, so the recovery is visible.

Why some routes are separate

TCG, Plush, newest-first, new-arrival, pre-order, and Amazon's TCG/plush/figure searches are distinct query scopes, not duplicate copies of the same page. They stay as separate route records so one route's results do not hide products that only appear in another search.

Only equivalent endpoints are treated as backups. PokéBeach's WordPress REST posts endpoint is a backup to its RSS feed, with the homepage used as a final news-page fallback. A route that already finds usable entries does not request its unused backup.

Identical URLs are reused within a scan process, and duplicate alerts for the same retailer/product/event are collapsed across routes.

Current versus last-known data

  • Current entries are products/articles recognized from a route actually checked in the current scan.
  • Last-known entries are saved from an earlier successful scan. They are kept for continuity after a parser miss, block, cooldown, scheduled interval, or request failure.
  • Tracked listings are deduplicated saved product records across retailers and routes; they are not a count of confirmed in-stock items.
  • Availability is shown only when a page exposes a recognizable stock indicator. Unknown availability is not guessed.

A blocked route starts a shared 45-minute retailer cooldown when no usable fallback is available. A retailer whose routes all fail at the request layer uses a shorter 15-minute cooldown. These pauses reduce repeated requests to a host that is not currently providing usable pages.

The GitHub Actions workflow is scheduled every 15 minutes, but GitHub may start scheduled runs late. The dashboard timestamp shows when a scan last wrote its state.
