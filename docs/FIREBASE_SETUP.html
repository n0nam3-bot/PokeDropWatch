Connect PokéDrop Watch

This is the exact setup guide for the website, subscriber database, email verification, and product-alert delivery. It includes direct console links, exact field names, and where each value belongs. No Vercel, Google Sheets, Firebase Hosting, Cloud Functions, or paid server is required.

Cost: This is designed for Firebase Spark, GitHub's free usage allowance, and Gmail. Each service has quotas; free does not mean unlimited email or database usage. Do not add billing or upgrade plans just to complete these steps.

Before starting — write down your GitHub owner and repository

  1. Open your PokéDrop Watch repository on GitHub.
  2. Its address looks like https://github.com/OWNER/REPOSITORY.
  3. OWNER is your GitHub username or organization. REPOSITORY is the repository name, without .git.
  4. Replace the words OWNER and REPOSITORY in GitHub links throughout this guide with your actual values.

For a normal project repository, the public website URL is https://OWNER.github.io/REPOSITORY/. If the repository itself is named OWNER.github.io, the URL is https://OWNER.github.io/ with no repository segment.

Firebase Authorized Domain: use only OWNER.github.io. Do not include https://, a slash, or the repository name.

1. Create your Firebase project

Open Firebase Console ↗

  1. Sign in with the Google account that will own PokéDrop Watch.
  2. Tap Create a project or Add project.
  3. Enter project name PokeDrop Watch, then continue.
  4. Choose Disable Google Analytics. Analytics is not used by this app.
  5. Finish creating the project. Keep it on the Spark (no-cost) plan; do not click Upgrade or add a billing account.
  6. Tap the gear beside Project Overview → Project settings → General. Copy the Project ID. Use this value wherever a link below says PROJECT_ID.

Direct Firebase links (replace PROJECT_ID)

Project overview · Firestore · Authentication providers · Authentication settings · Project settings · Service accounts

2. Create Firestore and publish its security rules

  1. Open https://console.firebase.google.com/project/PROJECT_ID/firestore using your Project ID, or tap the Firestore link above.
  2. Tap Create database. Choose Standard edition if prompted.
  3. Choose Start in production mode, not test mode.
  4. Select a location near you or most expected subscribers. The location cannot be changed after creation. Finish creating the database.
  5. Open the Rules tab.
  6. Open the raw rules file in another tab: firebase/firestore.rules (replace OWNER and REPOSITORY) ↗. Copy all of its text.
  7. Return to Firebase Rules, select and replace all starter text, then paste the copied rules.
  8. Find replace-with-your-admin-email@example.com in the Firebase editor. Replace it with your own lowercase administrator email, for example trainer@example.com.
  9. Tap Publish.
Keep the real admin email private: enter it only in the deployed Firebase Rules editor. Leave the placeholder in GitHub's public firebase/firestore.rules file. Never place the real address in docs/firebase-config.js.
When upgrading an existing Firebase project: uploading files to GitHub does not publish Firestore Rules. After installing v1.2.0 or a later rules-changing release, repeat this step using the latest firebase/firestore.rules from your repository. Keep your real lowercase administrator email in the Console rules, preserve any intentional project-specific changes, and tap Publish. v1.2.0 adds the accessories preference category; until the rules are republished, accessory subscriptions may be rejected.

3. Enable passwordless email-link sign-in

  1. Open Firebase Authentication providers ↗ (replace PROJECT_ID).
  2. If the page shows Get started, tap it.
  3. Open the Sign-in method or Sign-in providers tab.
  4. Select Email/Password, turn on Enable, and also turn on Email link (passwordless sign-in).
  5. Save the provider settings.
  6. Open Authentication settings ↗.
  7. Find Authorized domains → Add domain. Enter OWNER.github.io only (replace OWNER with your GitHub username/org), then add/save it.
  8. If you use a custom domain, add that hostname separately too.

Example: the Pages URL https://example-user.github.io/PokeDropWatch/ means the authorized domain is exactly example-user.github.io.

4. Register a Firebase Web App and fill in the public website config

  1. Open Firebase Project settings ↗.
  2. Scroll to Your apps, tap the Web icon (</>), and enter nickname PokeDrop Watch Website.
  3. Do not set up Firebase Hosting. The site is served by GitHub Pages. Tap Register app.
  4. Firebase shows a firebaseConfig object. Keep the page open.
  5. Open docs/firebase-config.js in GitHub editor ↗ (replace OWNER and REPOSITORY).
  6. Copy the values from Firebase into the matching existing fields:
GitHub file fieldCopy Firebase field
apiKeyapiKey
authDomainauthDomain
projectIdprojectId
appIdappId
messagingSenderIdmessagingSenderId
  1. Change only the text inside the quotes; keep the field names, quotes, commas, and braces.
  2. Do not paste a service-account JSON file into this file. Tap Commit changes and commit to main.

The Firebase Web App config is public browser configuration. It is not a password. The service-account JSON in Step 5 is private and must never go in a website file.

5. Generate the private Firebase service-account key

  1. Open Firebase Admin SDK service accounts ↗ (replace PROJECT_ID).
  2. In the Firebase Admin SDK section, tap Generate new private key.
  3. Confirm and download the JSON file.
  4. Open the JSON in a text viewer. Copy the entire contents, from the first { to the final }. Do not copy only the private_key field.
  5. Keep the file private. You will paste its complete text into a GitHub Actions secret in Step 7. Never upload the JSON file into GitHub or a ZIP.

6. Create a Gmail App Password for product alerts

Firebase sends email-link verification. Gmail sends separate product-alert emails.

  1. Sign in to the Gmail account that will send product alerts.
  2. Open Google Account Security ↗.
  3. Under How you sign in to Google, enable 2-Step Verification if it is not already enabled.
  4. Open Google App Passwords ↗.
  5. Create an App Password named PokeDrop Watch (or another descriptive label).
  6. Copy the generated 16-character App Password. Remove display spaces before pasting it into GitHub.
Do not use your normal Gmail password. If Google does not offer App Passwords for this account, stop here; some account types and security policies do not support them. An alternative email-provider integration would need to be implemented and tested separately.

7. Add exact GitHub Actions secrets and variable

Open repository Actions secrets ↗ (replace OWNER and REPOSITORY).

Under Repository secrets, tap New repository secret. Create these three required secrets using the exact uppercase names:

Secret nameValue
FIREBASE_SERVICE_ACCOUNT_JSONEntire JSON file contents copied in Step 5.
SMTP_USERNAMEFull Gmail sender address, e.g. pokedrop.alerts@gmail.com.
SMTP_APP_PASSWORD16-character App Password from Step 6, without spaces.

Optional secrets:

Secret nameValue / purpose
ALERT_EMAILYour email for an extra owner-only copy of each alert digest. Leave unset if not needed.
SMTP_HOSTUsually leave unset; defaults to smtp.gmail.com.
SMTP_PORTUsually leave unset; defaults to 587.

Add the website URL as a repository variable

  1. Open Repository Actions variables ↗.
  2. Under Repository variables, tap New repository variable.
  3. Name: PUBLIC_SITE_URL.
  4. Value: your full Pages URL including the last slash, e.g. https://example-user.github.io/PokeDropWatch/.
  5. Tap Add variable.

PUBLIC_SITE_URL belongs in Variables, not Secrets. The JSON key and Gmail App Password belong in Secrets, never Variables.

8. Install or replace the GitHub Actions workflow

The workflow must be at this exact path: .github/workflows/pokedrop-watch.yml. Use the separate pokedrop-watch.yml file supplied with this release.

  1. In your repository's Code tab, open .github → workflows → pokedrop-watch.yml.
  2. Tap the pencil/Edit button and replace the entire file with the supplied workflow file contents.
  3. Commit to branch main.

If the file does not exist: choose Add file → Create new file, enter the full filename .github/workflows/pokedrop-watch.yml, paste the supplied workflow contents, and commit to main.

Direct workflow edit link ↗ (replace OWNER and REPOSITORY).

Do not add workflow files to normal application patch ZIPs. The patch installer blocks .github/workflows/; edit this one-time workflow directly in GitHub.

9. Publish the real website using GitHub Pages

Open GitHub Pages settings ↗ (replace OWNER and REPOSITORY).

  1. Under Build and deployment, set Source to Deploy from a branch.
  2. Branch: main.
  3. Folder: /docs (not /root).
  4. Tap Save.
  5. Open the Pages URL GitHub displays. The site's homepage is docs/index.html; the admin page is the same address plus admin.html.

The repository Code tab will still display README.md. This is normal. Visitors use the separate GitHub Pages URL.

10. Sign in to the administrator page

  1. Open your public site's /admin.html page (example: https://example-user.github.io/PokeDropWatch/admin.html).
  2. Enter the same lowercase admin email you placed in the deployed Firestore Rules in Step 2.
  3. Tap Email secure sign-in link.
  4. Open the email link in the same browser where you requested it.
  5. The page should show Subscriber overview. If access is denied, check the administrator email in the deployed Firestore Rules and publish again.

Firestore Rules—not a public JavaScript setting—decide which verified email can manage subscribers.

11. Run the first scan and test one subscriber

  1. Open the PokéDrop Watch Actions workflow ↗ (replace OWNER and REPOSITORY).
  2. Select workflow PokeDrop Watch, tap Run workflow, keep branch main, then confirm Run workflow.
  3. Open the new workflow run. A green check indicates the job completed; tap a step to read its log.
  4. On the public site, submit a test application with an email address you can access. Pick at least one category and one retailer (or leave All retailers selected).
  5. Open the Firebase sign-in link in that mailbox. The site should say the application is pending approval.
  6. Open /admin.html, sign in as administrator, find the pending test address, and tap Approve.
  7. Run the workflow manually again. The subscriber will receive a matching event when a later scan detects a new change.
  8. Test unsubscribe from the public page: enter the subscriber email, request a link, open it, and tap Confirm unsubscribe.
First scan is a baseline: it records what is already listed. It does not email every item already on a retailer page. Later scans create alerts for newly detected changes. Approving a subscriber does not send old alerts.

Common setup errors

Message / symptomWhat to check
Firebase is not configuredAll five values in docs/firebase-config.js must be replaced and committed. Reload Pages after deployment.
auth/unauthorized-continue-uri or unauthorized domainAuthentication → Settings → Authorized domains. Add OWNER.github.io as hostname only.
auth/operation-not-allowedAuthentication → Sign-in providers → Email/Password. Enable Email/Password and Email link (passwordless sign-in), then save.
Admin account not authorized / insufficient permissionsFirestore → Rules. Verify the deployed administrator email exactly matches the signed-in verified email; tap Publish again.
Firebase service account missingGitHub Settings → Secrets and variables → Actions. Confirm FIREBASE_SERVICE_ACCOUNT_JSON contains the complete JSON.
Product alert email failsConfirm SMTP_USERNAME is the Gmail address and SMTP_APP_PASSWORD is the App Password, not the usual Gmail password.
README appears instead of websiteGitHub Settings → Pages must publish branch main, folder /docs.
No emails after first scanFirst scan is a baseline. Confirm subscriber status is active, preferences match, and Gmail secrets exist.
