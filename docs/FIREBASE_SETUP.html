ONE-TIME OWNER SETUP

Connect the subscriber system

PokéDrop Watch uses Firebase Authentication and Firestore for verified applications, private subscriber records, approval, and unsubscribe confirmation. The public website stays on GitHub Pages.

This is designed for Firebase's no-cost Spark plan and a small, low-volume community. Firebase, GitHub Actions, and Gmail have quotas; free does not mean unlimited. Do not enable billing just to complete these steps.
1. Firebase project2. Email sign-in3. Web config4. GitHub secrets5. Publish site6. Test

1. Create Firebase and Firestore

  1. Open Firebase Console and create a project. Keep it on the Spark plan; Analytics is not required.
  2. Open Build → Firestore Database → Create database. Choose the database location carefully because it cannot be changed later.
  3. Open Firestore's Rules tab. Copy the entire file firebase/firestore.rules from the GitHub repository into the rules editor.
  4. In the Firebase Console rules editor, replace replace-with-your-admin-email@example.com with your lowercase administrator email. Publish the rules there. Keep the placeholder in the public GitHub copy; do not commit your real administrator email.

Do not leave Firestore in test mode. The published rules are what prevent a visitor from viewing or changing another subscriber's record.

2. Enable verified email-link sign-in

  1. Open Build → Authentication → Get started.
  2. Under Sign-in method, enable Email/Password and the Email link (passwordless sign-in) option.
  3. Open Authentication Settings → Authorized domains. Add YOUR-GITHUB-USERNAME.github.io (hostname only, no repository path).

Visitors receive a sign-in link. They must open it to prove mailbox ownership before an application is created. Unsubscribing requires another sign-in link and a separate confirmation button.

3. Register a Firebase web app

  1. Open Project settings → General → Your apps. Add a Web app; Firebase Hosting is not required.
  2. Copy the web SDK values.
  3. In GitHub, open docs/firebase-config.js. Replace the placeholders for apiKey, authDomain, projectId, appId, and messagingSenderId.
  4. Save and commit the file. The administrator email is deliberately not stored in public website JavaScript.

The browser config is public by design. Never paste the Firebase service-account private key into this file or any file in docs/.

4. Add private GitHub Actions secrets

  1. In Firebase Project settings → Service accounts, generate a new private key and download the JSON.
  2. In GitHub repository Settings → Secrets and variables → Actions, create secret FIREBASE_SERVICE_ACCOUNT_JSON and paste the full JSON file contents as its value.
  3. Create secret SMTP_USERNAME with the Gmail sender address.
  4. Create secret SMTP_APP_PASSWORD with that Gmail account's App Password (not the normal account password).
  5. Optionally create secret ALERT_EMAIL to receive an additional owner-only copy.
  6. Create Actions variable PUBLIC_SITE_URL with the complete Pages URL, including repository path, for example https://YOUR-GITHUB-USERNAME.github.io/REPOSITORY-NAME/.

Never upload the service-account JSON file to the repository or include it in a ZIP patch. If the key is exposed, revoke it and generate a replacement.

Replace .github/workflows/pokedrop-watch.yml with the release's supplied workflow file so it passes the two Firebase values into the monitor step. Workflow files are updated directly in GitHub, not through normal ZIP patches.

Gmail App Passwords require two-step verification and may be unavailable for some account types or administrator policies. Gmail sending limits apply; start with a small group.

5. Publish the actual website

  1. In the repository open Settings → Pages.
  2. Choose Deploy from a branch, branch main, folder /docs, then Save.
  3. Open the Pages URL GitHub displays. It normally looks like https://YOUR-GITHUB-USERNAME.github.io/REPOSITORY-NAME/.

The repository Code tab will always show the README. Visitors use the separate Pages URL. The website starts at docs/index.html; the private admin page is /admin.html below the same Pages base URL.

6. Test the full flow

  1. Submit a test application from the public site using an email address you can open.
  2. Open its Firebase email link. The page should confirm the application is pending admin approval.
  3. Open the Administrator link, enter the admin email configured privately in Firestore rules, request its secure link, and sign in.
  4. Approve the test application in the admin dashboard.
  5. Run the GitHub Actions workflow manually. New matching product events will be sent to active subscribers; approving someone does not trigger historical alerts.
  6. Test unsubscribe: request a fresh link from the public site, open it, and press Confirm unsubscribe.

Subscriber email addresses stay in Firestore. They are not written to the public dashboard status file or shared with other subscribers.
